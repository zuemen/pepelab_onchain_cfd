# 合規責任邊界

> **草案**（2026-09-30）。**本文件不是法律意見。** 內容是 PepeFi 對白標合作中責任分工的初步描述，
> 用來協助持牌客戶與其法律顧問起草契約與進行盡職調查。所有標示「**需律師確認**」的項目，
> 都必須由客戶所在法域的執業律師確認；標示「**需客戶確認**」的項目，屬於客戶的商業或風險決策。
> PepeFi 目前是測試網研究原型，未取得任何法域的金融業務許可。

## 1. 基本原則

- PepeFi 提供**技術基礎設施**（合約、keeper、agent 工具、資料 API、前端範本），**不直接對公眾提供**
  衍生品、代幣化資產或投資建議服務。
- 對終端客戶的服務、契約關係與合規責任，由**持牌客戶**承擔。
- 鏈上合約只能強制它看得到的規則（例如限額、價格新鮮度、KYC 旗標）。法規要求的大部分義務
  （身分確認、適合度、揭露、申報）發生在鏈下，必須由客戶的流程完成。

## 3. 客戶負責什麼

| 項目 | 說明 | 狀態 |
|---|---|---|
| **牌照** | 在其服務的法域取得提供衍生品（CFD、期貨、槓桿交易）或代幣化資產服務所需的許可。合成資產中有 6 檔參照真實證券（sAAPL、sTSLA、sNVDA、sMSFT、sGOOGL、sBOND），對公眾提供槓桿曝險在幾乎所有法域都需要許可 | **需律師確認** |
| **KYC／AML** | 客戶身分確認、受益人辨識、制裁名單篩檢、持續監控、可疑交易申報。`KYCRegistry` 只記錄結果，不做審查 | **需律師確認** |
| **Travel Rule** | 若涉及虛擬資產移轉，依 FATF 建議第 16 項與當地法規傳遞發送方與受益方資訊 | **需律師確認**是否適用 |
| **適合度與適當性** | 評估終端客戶是否適合槓桿商品、代幣化資產或授權 AI agent 代為交易 | **需律師確認** |
| **槓桿上限** | 依法規設定。例如歐盟 ESMA 2018 年對散戶 CFD 採取的暫時性產品干預措施（其後已由各國主管機關以國內措施實施，實際適用以各國措施為準）的上限：主要貨幣對 30:1、非主要貨幣對／黃金／主要指數 20:1、黃金以外商品與非主要指數 10:1、個股與其他 5:1、加密資產 2:1。合約的全域上限是 5×，逐資產上限與碳分級只會更低，**不會自動符合**任何特定法規 | 參數由客戶設定；**需律師確認**適用規則 |
| **保證金平倉規則** | 例如 ESMA 要求帳戶保證金降到 50% 時平倉。合約的清算門檻是維持保證金率（預設 5%），與此不同 | **需客戶確認**如何在鏈下或以參數實現 |
| **負餘額保護政策** | 在上述 ESMA 措施及各國的國內措施下，對散戶的**逐帳戶負餘額保護是強制要求**，不是可選政策。逐倉下合約不向交易者追討超過保證金的虧損（見 [`RISK_WATERFALL.md`](RISK_WATERFALL.md)），但這是逐部位而非逐帳戶的保證，且 ADL 可能削減其他客戶的獲利、壞帳可能發生。客戶必須確保以帳戶為單位符合要求，並決定對終端客戶的揭露 | **需律師確認** |
| **風險揭露** | 標準化風險警語、合成資產不是證券、非足額抵押、ADL、預言機信任假設、測試網與未稽核狀態 | **需律師確認**文字 |
| **資料駐留與個資** | 目前 signal-api 部署在 Vercel `sin1`（新加坡）；前端在 Vercel；結算佇列在 Upstash Redis（區域**未驗證**）；CI 在 GitHub Actions。鏈上資料公開且不可刪除。客戶須決定個資是否可以離開其法域，以及哪些資料絕不可上鏈 | **需客戶確認**；**需律師確認** |
| **事故通報** | 對主管機關與終端客戶的通報義務與時限。我方依 [`INCIDENT_RESPONSE.md`](INCIDENT_RESPONSE.md) 通知客戶 | **需律師確認**法定時限 |
| **稅務與會計** | 交易、費用、代幣化資產的稅務處理 | **需律師確認** |
| **客戶資產保管與分離** | 目前保證金集中在 exchange 合約，沒有依客戶分帳的鏈下帳務；是否符合分離保管要求 | **需律師確認** |
| **治理與金鑰** | 規劃中：owner、guardian 等金鑰由客戶控制的 multisig 持有 | **需客戶確認** |

## 4. 委外契約應涵蓋的項目（一般描述）

持牌機構把核心業務系統委外時，多數法域的主管機關要求契約涵蓋下列事項（例如各地的作業委外規範、
歐盟 DORA 對 ICT 第三方服務的要求）。以下是**一般性清單**，具體條款與適用法規**需律師確認**：

1. **金檢權與稽核權**：主管機關與客戶（或其委任的稽核人員）可檢查我方與服務相關的程式碼、紀錄、
   流程與人員；我方配合提供資料的方式與時限。
2. **保密**：客戶資料、終端客戶資料、金鑰與營運資訊的保密義務，以及人員的保密約定。
3. **禁止或限制複委託**：我方不得在未經客戶同意下，把服務的重要部分再委託第三方；現有依賴的第三方
   （例如 Vercel、GitHub、Upstash、x402 facilitator、公開價格資料源）需列冊並取得同意。
4. **服務水準與變更管理**：可用性、回應時限、合約升級與 cutover 的通知與核准程序。
5. **資訊安全**：安全要求、漏洞處理、稽核報告的提供，以及未取得第三方稽核前的使用限制。
6. **事故通報**：我方通知客戶的時限與內容（見 [`INCIDENT_RESPONSE.md`](INCIDENT_RESPONSE.md)）。
7. **營運持續與退場**：
   - 服務中止或終止時，客戶取得原始碼、部署腳本、設定與資料的方式。
   - 移交金鑰或以客戶控制的金鑰重新部署的程序。
   - 終止後的過渡期支援與既有部位的處理方式。
8. **雲端與資料處理**：資料存放區域、資料處理者角色、跨境傳輸、刪除與返還、次處理者清單。
9. **智慧財產權與授權**：程式碼授權範圍（本 repo 目前**沒有授權條款檔案**）、客戶修改的歸屬。
10. **責任與賠償**：責任上限、排除事項、保險。
11. **終止權**：主管機關要求、重大違約、資安事件時客戶的終止權。

## 5. 本文件不涵蓋

- 任何特定法域的法律分析或牌照判斷。
- 合成資產或代幣化資產是否構成證券、衍生品或其他受規範商品的判斷。
- 終端客戶契約、風險揭露書的具體文字。
