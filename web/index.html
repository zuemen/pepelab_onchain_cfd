The agent economy

Machines that pay, read, and trade — autonomously.

AI agents discover tools over MCP, pay per request over x402, and trade only inside limits the account holder sets on-chain. All of it runs on testnet today.

⚡

x402 paid data

Agents hit HTTP 402, sign a USDC authorization, and get data back. Invalid requests are rejected before any payment is requested, and the service refuses to request payment if its payout address fails a safety check.

GET /signals/:trader · 0.01 USDC · GET /oracle/:asset · 0.005 USDC
🧩

MCP tool layer

Seven Model Context Protocol tools: five read-only (get_trader_performance, get_funding_rate, get_position, get_session, get_agent_verification) and two that send transactions (open_position, close_position) within a session and a signed authorization.

7 tools · 5 read · 2 write · stdio
🔑

Bounded agent sessions

The account holder creates a session on-chain: per-trade margin cap, total margin budget, max leverage, expiry and an optional asset allowlist. The contract enforces them; the holder can revoke at any time.

AgentSessionManager.sol
💸

Data revenue share

x402 revenue is split 70 / 20 / 10 (trader / platform / insurance vault) by a separate settlement transaction after payment — queued, not atomic with the payment itself.

70 / 20 / 10 · async settlement
🛰️

Keeper-relayed prices

The live exchange settles on a keeper-written oracle with a circuit breaker and fallback sources — a trusted relay, not a decentralized oracle. Chainlink / Pyth adapters exist but are not wired into the live exchange.

stale-price guard · 6h
🌱

Carbon-tier synthetic assets

Synthetic exposure to equities, commodities, bonds and ESG baskets. Fees and leverage caps follow each asset's attested carbon tier; unrated assets fall to the most conservative tier. Synthetic exposure only — not the underlying securities.

Copy trading, on-chain

Mirror the best. In one transaction.

Follow a trader and their strategy is replicated to your account by weight, leverage and direction — enforced by contracts, with the trader's stake slashable on large losses. Leveraged copy trading is off by default in the commercial build (feature flag); it remains in the codebase for evaluation.

02

One click mirrors allocations — BTC 50%, ETH 30%, AAPL 20%.

03

Auto-managed

Funding auto-settles, stale prices are blocked, losses can slash the trader's stake.

04

Unfollow anytime

One call closes every mirrored position and returns margin + profit.

Security status

Honest about what is not done yet.

No third-party audit. The contract owner is a single key — no multisig, no timelock. What exists is internal review, static analysis and invariant tests. Details: SECURITY.md and docs/KNOWN_LIMITATIONS.md in the repository.

🛡️

Reentrancy guards

The exchange, insurance vault, session manager and V2 token vault use nonReentrant on fund-moving paths. Older V1 contracts do not use SafeERC20 — a documented limitation.

⏱️

Stale-price guard

maxPriceAge (6h on the live exchange) reverts trades on outdated oracle data.

🎯

Liquidations & loss absorption

Liquidators earn 5% of remaining collateral. Shortfalls go to the insurance vault, then auto-deleveraging, then an on-chain bad-debt event — solvency is not guaranteed.

🔁

Funding catch-up

Funding settlement accounts for every missed 8h interval when it is next cranked.

🔐

Bounded delegation

Agents act only inside on-chain session limits; the account holder's key is not handed to the agent.

🧪

Not audited

Tests run in CI (Foundry, Vitest, agent suites). Tests are not an audit; pause, halt and risk-cap controls exist in source only and are not yet deployed.
