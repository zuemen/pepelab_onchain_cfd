# 路線圖：跟單同意範圍與協議風控（借鏡 Hyperliquid、eToro）

> 狀態：**提案，未實作**（2026-10-26）。來源是使用者當天的「Hyperliquid × eToro 平台研究」。
> 已決定的範圍：先完成 ADR-024 的部署與展示，P0 留到下一輪。
> 本文件只收「對照 repo 現況後仍然成立」的建議。研究裡和現況不符的說法，在下一節逐條更正。

## 研究說法與 repo 現況的對照

| 研究的說法 | repo／鏈上現況（2026-10-26 讀回） | 結論 |
|---|---|---|
| `maxPriceAge` 是 24 小時 | 原始碼預設 24 小時；Base Sepolia 交易所實際是 **6 小時**（21600 秒），由 #344 cutover 設定；上限常數 `MAX_PRICE_AGE_LIMIT` 是 7 天 | 方向對，數字要更正 |
| 把同步的價格新鮮度要求降到 60 秒 | 測試網 keeper 由 GitHub 排程觸發，10/21 以來實際最長間隔 5.83 小時（`OWNER_ACTIONS` 第 2 步要改用 Cloudflare 觸發） | 照做的話自動同步幾乎永遠會被擋。要先有分鐘級的 keeper，或改成跟隨者可設定的上限 |
| 清算是「5% 給清算人、95% 進保險金庫」一次清光 | `LIQUIDATION_REWARD_BPS = 500`，單次全清；另有 ADL（`adlEnabled`）與保險金庫 | 正確；分段清算是有效建議 |
| 每個資產設未平倉量上限 | 已有：`setMaxOpenInterest(asset, maxLong, maxShort)`、`OpenInterestCapExceeded` | 已實作，不列入 |
| 提領保證金至少保留 max(初始保證金, 10% 部位價值) | 部位是逐倉，保證金鎖在部位上；`withdrawMargin` 只能領 `freeMargin` | 這個設計下不適用 |
| 資金費率可以改成 F = P̄ + clamp(r − P̄, ±0.05%) | 現行是 8 小時結算的 OI 失衡費率（`FUNDING_INTERVAL = 8 hours`） | 可列為協議層提案，要另行建模 |
| 「P0–P2 都可以在現有的 setAutoSync、resyncFor 與 agent 程式內調整，不需要新增合約方法」 | 停損、改版上限、卡版預設動作都要新增同意參數（改 `setAutoSync`／`followTraderAtVersionWithAutoSync` 簽章或加新函式），並改 `_resync` | 不成立：需要合約改版、重新部署 CopyTracker |

## 建議（依優先序）

### P0：擴大「跟隨者同意的範圍」（CopyTracker 改版，下一輪）

1. **無需許可的跟單停損**：同意時寫入停損門檻（例如投入額的 40%）。`resyncFor` 發現這筆跟單的權益低於門檻時，動作改成「全部平倉、結束跟單」。
   - 這是固定規則，和清算同類，不需要任何人的裁量，所以可以無需許可。
   - 要處理：權益要用交易所的標記價計算；平倉後照 `unfollowAndCloseAll` 的規則計分。
2. **改版幅度上限**：同意時寫入單一資產權重上限、允許的資產類別（例如不含 RWA）或碳分級。新版超出範圍時同步 revert，執行者把它分類為需要本人重新同意，並發通知。
3. **卡版時的預設動作**：新版開不了倉（KYC、休市、`MarginTooLow`）時，依同意值處理：留在舊版（現行行為），或平倉成現金。
4. **價格新鮮度**：同步時要求 oracle 價格比交易所的 `maxPriceAge` 更新，門檻由跟隨者設定。前提是 keeper 先改成分鐘級（`OWNER_ACTIONS` 第 2 步）。

### P1

5. **只調差額**：同資產、同方向的腿只加減部位，不全平再全開。要處理部分平倉與保證金重算，CopyTracker 大小會增加（ADR-024 Considered options 已列為暫緩）。
6. **同意的到期與累計上限**：同意時帶到期時間與累計執行費上限；到期前，personal 執行者或只通知模式提醒續簽。
7. **交易者自留部位與高水位績效費**：績效費改為只在創新高時收（KNOWN_LIMITATIONS #41 的根本修法），這要改 PerpetualExchange，而它的 runtime 大小已接近 EIP-170。

### P2

8. **跟隨者端 AI 只能收緊**：主錢包授權的 agent 只能暫停同步、調低上限；放寬或提領一律要主錢包簽名。
9. **多個執行者競爭**：公開執行者可以多開，縮小單一執行者挑時機的空間。
10. **管理金鑰改為多簽加 timelock**：`HandoverToTimelock.s.sol` 已有，位址常數要先更新（CUTOVER_LOG_2026-10-20「待擁有者」）。

### P3

11. **可選的池化模式**：給想要完全即時的人，另做金庫模式；自託管仍是預設。

## 協議層（不屬於跟單，列為後續）

- **標記價與 oracle 分開**：例如取三個價格的中位數。現在 `markPremiumCapBps = 0`，也就是標記價等於指數價。
- **分段清算**：大部位每次只清一部分，並設冷卻時間。
- **資金費率改為小時制加上限**。
- **Builder code 分潤**：第三方前端或 x402 API，在使用者授權下收上限內的費用。

## 不做的事（與研究一致）

- 平台替使用者下單。
- 把私鑰交給 agent。
- 事後投票改結算。
- 讓改版帶來無上限的成本：已由冷卻與簽名帶入的費率上限擋住。

## 給教授的講法（更正後）

PepeFi 讓資金留在跟隨者自己手上：跟隨者簽一次同意，任何 agent 都能觸發同步，但內容由合約決定。
- 代價是同步至少隔一個冷卻時間（合約下限 1 小時），以及「全平再開」的交易費。
- 下一輪會把停損與改版上限也寫進同意範圍。
- 平台是測試網上的研究原型。台灣對跟單與 CFD 有牌照要求（金管會 2019、2020 年對 eToro 的處置），本文不是法律意見。
