# 本平台是 RWA 的衍生品與配置層,不做發行

推動 RWA 有三條路,而這個系統只走得了其中一條。**發行端**要託管機構、法律包裝、發行人關係 —— 我們一樣都沒有,四週內也生不出來。**合規端**要身分層、合規模組、跨管轄規則 —— 我們有一個天真版的 `KYCRegistry`,但 ERC-3643/T-REX 已經把這塊做完了,我們只能做增量。**需求端**要定價場所、持有理由、可負擔的工具 —— 那正是這個系統已經蓋出來的東西。

盤點的結論是:RWA 的瓶頸已經不在「能不能上鏈」。代幣化國庫券在主網已有規模,供給端動了;但它們躺在錢包裡,沒有持續的價格發現、沒有避險工具,而對散戶來說一個代幣化的 S&P ETF 嚴格劣於一個券商帳戶 —— 沒有稅務包裝、沒有投資人保護、UX 更差。**沒有人需要它。**

決定是把本平台定位為 **RWA 的衍生品與配置層**:不碰發行、不碰託管、不碰法律請求權,專做「資產上鏈之後」那一段 —— 持續定價、一個券商給不了的持有理由(見 ADR-003)、以及讓小額投資人也用得起的配置工具。

這個定位一次解掉三個一直卡住的問題。**「合成資產不算真 RWA」的攻擊消失了** —— 期貨交易所也不持有現貨,而歷史上大宗商品的現貨市場正是先有衍生品市場才變得有流動性;我們不是在假裝持有標的,衍生品層本來就不持有標的。**「鏈下那一腿」從弱點變成分工** —— 系統邊界就是不碰發行,而 `docs/RISK_MODEL.md` 開頭那句「Audience: the risk function of an institution deploying this engine」早就把營運者設定為受監管機構,發行歸發行,我們做它上面那一層。**ERC-3643 那條線降級** —— 它屬於合規端,不是我們的路線。

## Considered options

**做發行端 —— 把資產真的搬上鏈。** 需要託管、法律包裝、發行人關係與贖回為實體資產的流程。四週內只能做一個演出來的版本,而演一個託管人比不做更傷:它會讓真正誠實的部分一起被懷疑。

**做合規端 —— 把 `KYCRegistry` 認真升級到 ERC-3643。** 技術含量足夠,但它和已經蓋好的東西吻合度低,而且碳定價會退成配角。查證結果也不利:T-REX 是 GPL-3.0、Solidity 固定 0.8.17、OpenZeppelin 4.8、ONCHAINID 為另一套依賴,與本專案的 MIT / 0.8.20 / OpenZeppelin v5 全面衝突,原 repo 並已於 2025-10-28 封存。

**假設 RWA 已成熟,做一個成熟市場裡的產品。** 這是本案最初的框架,後來推翻。它讓平台變成一個假想市場裡的產品展示;「假設要推動 RWA」才讓它變成一份機制設計提案 —— 前者是作品,後者才是研究貢獻。

## Consequences

- 論文的系統邊界必須明講:不解決資產怎麼上鏈,並用期貨交易所的類比說明為什麼衍生品層不持有標的是正常而非缺陷。
- `AssetVault` 系列「非足額抵押」的既有自白不再是需要辯解的弱點,而是這一層本來的風險形態。儲備紀律的處理見 ADR-004。
- 供給端的論證靠文獻:引用真實存在的代幣化 RWA 佐證供給端已部分啟動,缺的那半在需求端。
- 既有的 `StrategyRegistry` / `CopyTracker` / `TraderStake` 從「跟單交易」重新理解為模型投資組合與信譽擔保,不需重寫。
- 若日後要進入發行端或合規端,本 ADR 需重新檢視 —— 它們不是被否定,是被排在這一輪之外。
