# 儲備透明度用事件與自動反應補齊,不加鏈下見證人

一個「代幣化資產」平台通常要回答兩個問題:欠持有人多少、手上是不是真的有。交易所倒閉多半是第二題的答案是「沒有」,而且沒人查得到 —— 標準做法是 Merkle 負債樹加上一份稽核師簽署的儲備證明。

本專案的情況不一樣,而這一點差點被誤判。`AssetVaultV2_2` 的**兩邊都已經在鏈上**:`reserve()` 讀的是合約自己的 USDC 餘額(扣掉應計費用),`outstandingValue()` 用預言機逐一計價負債,`reserveRatioBps()` 是 public,`mint()` 破線直接 revert,而 `ratioIsStale()` 還誠實回報「有資產無法計價,所以這個比率是樂觀的」。任何人都能自己驗證,不需要信任任何人。

因此**不加鏈下見證人**。在一個不需要信任的系統裡插入一個要被信任的角色,那不是加強,是倒退;Merkle 負債樹對本專案也是白工,因為負債本來就公開。

真正缺的是三件,而且都和「誰簽名」無關。**歷史無法證明**:能讀到現在的比率,但無法證明上週二是多少 —— 沒有事件。README 整節在自豪「每個狀態改變都發事件、`/history` 可以重播」,唯獨這個最該被重播的數字沒有。**破線沒有任何反應**:負債是逐日盯市的,價格漲一倍負債就漲一倍而儲備不動,比率可以在沒有人做任何動作的情況下破線;`mint()` 擋得住新鑄造,但已經在裡面的贖回者沒有保護、沒有事件、沒有警報。**`ratioIsStale()` 沒有讀者**:它是一個沒有人消費的誠實。

決定是以一次 UUPS 原地升級補齊這三件 —— 新增帶儲備、負債、比率、無法計價資產數與時間戳的觀測事件,由既有 keeper 定期敲;比率跌破門檻時發出破線事件並自動暫停鑄造;前端在 `ratioIsStale()` 為真時顯示「無法確認」而不是一個樂觀數字。不換位址、不新增合約、不新增私鑰。

**贖回永遠不受儲備率限制。** 壓力期間阻擋退出是擠兌本身,不是防線 —— `docs/RISK_MODEL.md` 已經是這樣寫的,本 ADR 把它列為不可違反。

## Considered options

**加一個 attestor 角色簽署帶時間戳的儲備聲明,過期就 fail-closed 擋住鑄造。** 這是本案最初的方案,前提是「負債在鏈上、資產那半在鏈下」。讀過 `reserve()` 之後前提被推翻:資產那半是合約自己的 USDC 餘額,也在鏈上。方案因此不只是多餘,而是有害 —— 它會替一個無需信任的量引入一個信任假設,並且多一組要保管的私鑰。

**做 Merkle 負債樹。** 交易所的標準做法。對本專案是白工:所有部位都在鏈上,任何人都能自己加總。

**只把既有的 `reserveRatioBps()` 顯示在前端,不動合約。** 最便宜,但它留下「破線沒有反應」與「歷史無法證明」兩個缺口,而那兩個才是真正的風險。

## Consequences

- 補齊的成本比原方案低:一次 UUPS 升級,無新合約、無新角色、無新私鑰。
- 前端必須消費 `ratioIsStale()`,並在為真時顯示「無法確認」。這與詞彙表 `KYC Status` 的 `unknown` 不是軟性 `verified`、閘門 fail-closed 是同一套哲學。
- keeper 多一個定期敲觀測事件的工作,需納入既有 keeper 的執行與測試。
- 自動暫停鑄造是一個新的失效模式:價格劇烈上漲會讓平台在無人操作下停止鑄造。這是刻意的,但需在文件中說明,避免被當成故障。
- 「我們一直都是超額儲備」這句話從此可以被任何人用事件重播驗證,而不是只能相信當下的讀值。
