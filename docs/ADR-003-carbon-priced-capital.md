# 資金成本由碳強度決定,而且門檻是常數不是參數

平台需要一個「為什麼要在鏈上做這件事」的理由,而它必須經得起一句反問:這個用一個資料庫加券商 API 也能做,為什麼要上鏈?

答案不是「碳定價」本身 —— 券商技術上當然可以對高碳標的收較高手續費。**真正的差別是不可裁量且可稽核**:鏈上那條規則是任何人都能讀、能驗,而且營運方不能對個別客戶悄悄關掉。傳統結構下永續投資的規則和它的執行是分開的,規則寫在公開說明書裡、執行在機構內部,投資人只能事後看報告;資產上鏈之後,規則可以和資產放在同一個地方,變成資產移動時必須通過的那道檢查。承諾與執行合而為一。

決定是讓**碳強度直接決定持有成本與槓桿上限**:`PerpetualExchange` 的交易費率、借貸費率與最大槓桿從全域單值改為逐資產,全部由一個 `CarbonTiers` 純函式從碳強度推導。碳排越高,持有越貴、能用的槓桿越少。

兩個關鍵限制。**級距只有一個定義** —— Solidity 一份 library、TypeScript 一份對應,`PerpetualExchange`、`CopyTracker`、前端顯示與離線模擬全部呼叫它,並有測試把兩邊門檻釘在同一組斷言裡;各自實作會靜默漂移而沒有任何測試抓得到。**門檻值是常數,不是可設定參數** —— 可設定就等於可裁量,而不可裁量正是這整套論述唯一的立足點。

未評等的資產一律落到最保守級(1x、最高費率):fail-closed,既不是拒絕開倉也不是給予優惠。碳分級在開倉當下讀一次並寫入部位,不在每次計費時重讀,所以評等變動不會追溯改變既有部位的成本 —— 與 KYC 那條「開倉時檢查一次、不追溯」同一原則。

## Considered options

**用 ESG 綜合分當定價依據。** `ESGRegistry` 已經有 `compositeScore`,改動最小。否決的原因是它撐不住追問:綜合分是一堆主觀意見的加權平均,被問「你憑什麼說這家公司 82 分」時沒有答案。碳強度有單位、可稽核、幾乎沒有詮釋空間,而「碳可稽核、ESG 綜合分是意見」這句話是本案最強的一句 —— 用綜合分定價會親手拆掉它。ESG 的 E/S/G 分數退回顯示層。

**用准入限制而非定價。** 低 ESG 資產禁止或限額。否決:家長式,且與「使用者自己配置」的主角設定矛盾。定價讓使用者自己選,而成本結構誠實反映他宣稱在意的東西。

**發獎勵給高 ESG 持有者。** `EsgRewardDistributor` 已經在做。否決作為主要機制:獎勵可以靠開開關關來套利,30 天鎖定只是把它拖慢而非解決;定價的成本是持有期間持續發生的,無法迴避。該合約保留,但改發不可轉讓憑證(見 `SustainabilityBadge`)。

**門檻值做成可由 owner 設定的風險參數。** 和 `AssetVault` 的其他風險參數一致,也更靈活。否決:一個可以被營運方調整的門檻,就是一條可裁量的政策,而本 ADR 的全部價值在於它不可裁量。靈活性在這裡是缺陷不是特性。

## Consequences

- `PerpetualExchange` 必須重新部署 —— 它沒有 proxy,`oracle` 與 `usdc` 是 `immutable`。這連鎖強制重部署 `CopyTracker`(四個 immutable 上游)與 `EsgRewardDistributor`。既有欠著的 `FUNDING_INTERVAL` 修正搭同一班車。
- `CopyTracker` 的費用緩衝必須改為逐 `Allocation` 項目計算。它目前呼叫全域 `TRADING_FEE_BPS` 估算一份配置的手續費預算,費率逐資產化後會低估,含高低碳混合的配置會預留不足而開到一半失敗 —— **不會有編譯錯誤,只會在執行時出現**。
- 必須存在一個測試,證明**沒有任何路徑可以為個別使用者豁免費率**。它釘住的是一個缺席的功能,並擋住未來有人把它加回來。
- 機制有一個刻意的副作用:sBTC 會自動成為全平台持有成本最高的資產,sICLN 最低。平台不需要禁止任何東西,使用者跟著成本走就會離開投機性資產 —— 這是「不是炒幣平台」唯一可以被算出來而非被宣稱的版本。
- 碳資料必須全部來自真實公開來源並記錄出處,否則本 ADR 的前提失效。資料本身是否屬實不在本平台的解決範圍:公司若在自己的排放申報上說謊,鏈會忠實執行一個謊言;多方見證與歧見可見減輕但不解決。
